1. INTRODUCCIÓN

En las unidades anteriores, el alumnado ha aprendido a programar utilizando estructuras de control, funciones, arrays y objetos, desarrollando programas que se ejecutaban principalmente en consola. Sin embargo, en el desarrollo web real, el código se ejecuta dentro de un entorno concreto: el navegador.

En esta unidad se introduce el uso del navegador como entorno de ejecución, permitiendo al alumnado interactuar con el usuario, gestionar información y modificar el comportamiento de la aplicación en tiempo real.

Para ello, se trabajará con los objetos predefinidos del lenguaje y del navegador, que proporcionan funcionalidades listas para usar. Además, se introduce un aspecto clave en el desarrollo profesional: la organización del código en múltiples archivos mediante módulos, favoreciendo la reutilización y el mantenimiento del código.

Esta unidad supone un cambio importante, ya que el alumnado comienza a desarrollar aplicaciones más cercanas a la realidad, donde el código no solo resuelve problemas, sino que interactúa con el entorno y con el usuario.

2. UTILIZACIÓN DE OBJETOS. OBJETOS NATIVOS DEL LENGUAJE

JavaScript dispone de una serie de objetos nativos que permiten realizar operaciones comunes sin necesidad de implementarlas desde cero. Estos objetos forman parte del lenguaje y facilitan el desarrollo de programas más eficientes.

2.1 OBJETO MATH

El objeto Math proporciona métodos para realizar operaciones matemáticas.

Ejemplo:

let numero = 4.7;
console.log(Math.round(numero));  
console.log(Math.floor(numero));  
console.log(Math.ceil(numero));   
console.log(Math.random());

También permite generar números aleatorios en un rango:

let aleatorio = Math.floor(Math.random() * 10) + 1;

Muy útil en:

  • juegos
  • simulaciones
  • generación de datos

2.2 OBJETO DATE

El objeto Date permite trabajar con fechas y horas.

let fecha = new Date();
console.log(fecha.getFullYear());
console.log(fecha.getMonth());
console.log(fecha.getDate());

Permite:

  • obtener la fecha actual
  • trabajar con tiempos
  • mostrar información temporal

2.3 OTROS OBJETOS NATIVOS

  • String → manipulación de texto
  • Number → conversión de valores
  • Boolean → para trabajar con valores booleanos

Ejemplo:

let texto = "hola mundo";
console.log(texto.toUpperCase());
let numero = Number("10");

El uso de objetos nativos:

  • evita duplicar código
  • facilita la reutilización
  • mejora la eficiencia

Además, de estos objetos existen muchos más, que iremos descubriendo a medida que vayamos desarrollando nuestros proyectos con JavaScript.

3. INTERACCIÓN CON EL NAVEGADOR. OBJETOS PREDEFINIDOS

El navegador proporciona objetos que permiten interactuar con el entorno. El principal es el objeto window, que representa la ventana del navegador.

3.2 OBJETO CONSOLE

console.log("Mensaje");
console.error("Error");

Este objeto con el que ya hemos trabajado es fundamental para:

  • depuración
  • seguimiento del programa

4. GENERACIÓN DE TEXTO Y ELEMENTOS HTML DESDE CÓDIGO

Uno de los aspectos fundamentales del desarrollo web es la capacidad de generar contenido de forma dinámica. A diferencia de una página estática, donde el contenido está definido previamente en el archivo HTML, JavaScript permite crear, modificar y mostrar información en tiempo real.

Este apartado introduce al alumnado en la idea de que el código puede influir directamente en lo que el usuario ve en pantalla, sentando las bases para el trabajo posterior con el DOM en unidades siguientes.

4.1 CONCEPTO DE CONTENIDO DINÁMICO

El contenido dinámico es aquel que no está definido previamente en el HTML, sino que se genera o modifica mediante código.

Por ejemplo:

  • Mostrar un mensaje personalizado
  • Mostrar resultados de un cálculo
  • Crear elementos en función de datos

Ejemplo:

let nombre = prompt("Introduce tu nombre");
document.write("Hola " + nombre);

En este caso, el contenido que se muestra depende del usuario, por lo que no es estático.

4.2 USO DE DOCUMENT.WRITE()

El método document.write() permite escribir directamente en el documento HTML desde JavaScript.

document.write("Hola mundo");

También permite incluir etiquetas HTML:

document.write("<h1>Título</h1>");
document.write("<p>Este es un párrafo</p>");

Principales características

  • Es simple y directo
  • Se ejecuta en el momento de carga de la página
  • Inserta contenido en el documento

Limitaciones importantes

Aunque es útil para aprender, presenta inconvenientes:

  • Sobrescribe el documento si se ejecuta después de la carga
  • No permite modificar contenido existente
  • No se utiliza en aplicaciones reales

Ejemplo problemático:

document.write("Nuevo contenido"); // Borra todo lo anterior si se ejecuta tarde

4.3 MODIFICACIÓN DEL CONTENIDO DEL DOCUMENTO

Para superar las limitaciones de document.write(), se pueden utilizar propiedades del documento como innerHTML.

document.body.innerHTML = "<h1>Bienvenido</h1>";

Esto permite modificar el contenido existente de la página.

Qué permite hacer

  • Cambiar contenido
  • Insertar HTML
  • Mostrar resultados dinámicos

Ejemplo

let numero = Number(prompt("Introduce un número"));
let doble = numero * 2;

document.body.innerHTML = "<p>El doble es: " + doble + "</p>";

El contenido mostrado depende del cálculo.

Consideraciones

  • Reemplaza todo el contenido del body
  • Puede eliminar contenido previo si no se usa correctamente

4.4 GENERACIÓN DE CONTENIDO DINÁMICO CON ESTRUCTURAS DE CONTROL

JavaScript permite generar contenido en función de condiciones o repeticiones.

Uso con condicionales

let edad = Number(prompt("Edad"));

if (edad >= 18) {
    document.write("<p>Mayor de edad</p>");
} else {
    document.write("<p>Menor de edad</p>");
}

Uso con bucles

let numeros = [1, 2, 3, 4];

for (let i = 0; i < numeros.length; i++) {
    document.write("<li>" + numeros[i] + "</li>");
}
let nombres = ["Ana", "Luis", "Pedro"];

document.write("<ul>");

for (let i = 0; i < nombres.length; i++) {
    document.write("<li>" + nombres[i] + "</li>");
}

document.write("</ul>");

4.5 MOMENTO DE EJECUCIÓN DEL CÓDIGO (WINDOW.ONLOAD)

Cuando trabajamos con JavaScript en una página web, es importante entender que el código puede ejecutarse antes de que el HTML esté completamente cargado.

Esto puede provocar errores cuando se intenta acceder a elementos como document.body o elementos del documento.

Problema habitual

document.body.innerHTML = "<h1>Hola</h1>";

Este código puede fallar si el <body> aún no existe en el momento de ejecución.

Solución: window.onload

Para asegurarnos de que el documento está completamente cargado, se utiliza:

window.onload = function() {
    document.body.innerHTML = "<h1>Hola</h1>";
};

De esta manera, se espera a que la página se cargue completamente para ejecutar el código después, garantizando que los elementos HTML existen.

Ejemplo 

window.onload = function() {
    let numero = Number(prompt("Introduce un número"));
    let doble = numero * 2;

    document.body.innerHTML = "<p>El doble es: " + doble + "</p>";
};

4.6 BUENAS PRÁCTICAS INICIALES

En este nivel es importante introducir ciertas recomendaciones:

  • Evitar abusar de document.write() ya que esta deprecado.
  • Usar innerHTML de forma controlada
  • Asegurar la carga del documento (window.onload)
  • Separar lógica y presentación en la medida de lo posible
  • Mantener el código organizado

5. GESTIÓN DE LA APARIENCIA DE LA VENTANA

El objeto window permite acceder a información relacionada con la ventana del navegador y modificar su comportamiento. Esto resulta especialmente útil para adaptar la aplicación al entorno en el que se ejecuta.

5.1 PROPIEDADES DE LA VENTANA

El navegador proporciona información sobre el tamaño de la ventana:

console.log(window.innerWidth);
console.log(window.innerHeight);

Estas propiedades indican:

  • Ancho de la ventana
  • Alto de la ventana

Aplicaciones prácticas

  • Adaptar contenido según tamaño de pantalla
  • Mostrar información contextual al usuario
  • Simular comportamiento responsive 
if (window.innerWidth < 600) {
    document.write("Pantalla pequeña");
} else {
    document.write("Pantalla grande");
}

5.2 NAVEGACIÓN

El método location permite obtener información sobre la URL actual y modificarla.

console.log(window.location.href);

Redirección

window.location.href = "https://www.google.com";

Recarga de página

window.location.reload();

6. CREACIÓN DE NUEVAS VENTANAS Y COMUNICACIÓN

El navegador permite abrir nuevas ventanas o pestañas mediante código.

6.1 APERTURA DE VENTANAS

let nuevaVentana = window.open("https://www.example.com", "_blank");

Parámetros:

  • URL
  • tipo de apertura (_blank, _self)

6.2 INTERACCIÓN CON LA VENTANA

let nuevaVentana = window.open("https://www.example.com", "_blank");
nuevaVentana.document.write("Contenido en nueva ventana");

6.3 CONTROL DE LA VENTANA

let nuevaVentana = window.open("https://www.example.com", "_blank");
nuevaVentana.document.write("Contenido en nueva ventana");
nuevaVentana.close();

Ejemplo práctico

let ventana = window.open("", "_blank");
ventana.document.write("<h1>Hola desde otra ventana</h1>");

Aunque no es muy usado en aplicaciones modernas, nos permite trabajar:

  • Comprender el funcionamiento del navegador
  • Referencias a objetos
  • Comunicación entre contextos
  • Conceptos de aplicaciones multi-ventana

7. ALMACENAMIENTO Y RECUPERACIÓN DE INFORMACIÓN

En el desarrollo de aplicaciones web, es habitual necesitar guardar información para poder utilizarla más adelante. Esta información puede estar relacionada con el usuario, con la configuración de la aplicación o con datos generados durante la ejecución.

El navegador proporciona diferentes mecanismos para almacenar información en el lado del cliente, permitiendo que los datos se mantengan incluso después de cerrar la página o el navegador.

En esta unidad se trabajan principalmente:

  • localStorage
  • cookies

7.1 CONCEPTO DE ALMACENAMIENTO EN EL NAVEGADOR

El almacenamiento en el navegador permite guardar información de forma persistente en el dispositivo del usuario.

Esto permite:

  • mantener datos entre sesiones
  • evitar pedir continuamente la misma información
  • mejorar la experiencia de usuario

Ejemplos de uso:

  • guardar el nombre de usuario
  • recordar preferencias (tema oscuro, idioma…)

7.2 ALMACENAMIENTO CON LOCALSTORAGE

El objeto localStorage permite almacenar datos de forma persistente en el navegador mediante pares clave-valor.

7.2.1 Características de localStorage

  • Persistente → no se borra al cerrar el navegador
  • Formato clave-valor
  • Solo almacena texto
  • Gran capacidad (comparado con cookies)
  • Fácil de usar

7.2.2 OPERACIONES BÁSICAS

Guardar datos

localStorage.setItem("nombre", "Ana");

Recuperar datos

let nombre = localStorage.getItem("nombre");
console.log(nombre);

Eliminar datos

localStorage.removeItem("nombre");

Eliminar todo

localStorage.clear();

7.2.3 USO CON VARIABLES DINÁMICAS

let nombre = prompt("Introduce tu nombre");
localStorage.setItem("usuario", nombre);

7.2.4 USO CON OBJETOS

Como localStorage solo almacena texto, es necesario convertir los objetos a formato JSON.

Guardar objeto

let usuario = {
    nombre: "Ana",
    edad: 20
};

localStorage.setItem("usuario", JSON.stringify(usuario));

Recuperar objeto

let datos = JSON.parse(localStorage.getItem("usuario"));
console.log(datos.nombre);

7.3 ALMACENAMIENTO MEDIANTE COOKIES

Las cookies son un mecanismo tradicional de almacenamiento que permite guardar información en el navegador en forma de texto.

  • Se almacenan como cadenas de texto
  • Tienen una fecha de expiración
  • Se envían automáticamente al servidor
  • Tienen menor capacidad que localStorage

7.3.1 ESTRUCTURA DE UNA COOKIE

nombre=valor; expires=fecha

7.3.2 CREAR UNA COOKIE

document.cookie = "usuario=Ana";

7.3.3 Cookie con expiración

let fecha = new Date();
fecha.setTime(fecha.getTime() + (24 * 60 * 60 * 1000));
document.cookie = "usuario=Ana; expires=" + fecha.toUTCString();

7.3.4 Leer cookies

console.log(document.cookie);

Resultado:

usuario=Ana; tema=oscuro

7.3.5 ELIMINAR COOKIES

document.cookie = "usuario=; expires=Thu, 01 Jan 1970 00:00:00 UTC";

Limitaciones de las cookies

  • Más complejas de gestionar
  • Menor capacidad
  • Se envían en cada petición (puede afectar al rendimiento)

7.4 COMPARACIÓN ENTRE LOCALSTORAGE Y COOKIES

Interpretación

  • localStorage → ideal para aplicaciones cliente
  • cookies → útiles cuando se necesita comunicación con servidor

7.5 BUENAS PRÁCTICAS EN ALMACENAMIENTO

En este nivel es importante introducir hábitos correctos:

  • Usar nombres claros para las claves
  • Evitar almacenar información sensible
  • Comprobar si los datos existen antes de usarlos
  • No abusar del almacenamiento

Ejemplos

let usuario = localStorage.getItem("usuario");

if (usuario) {
    console.log("Usuario encontrado:", usuario);
} else {
    console.log("No hay usuario guardado");
}
// Pedir nombre
let nombre = prompt("Introduce tu nombre");

// Guardar en localStorage
localStorage.setItem("usuario", nombre);

// Guardar en cookie
document.cookie = "usuario=" + nombre;

// Mostrar resultados
console.log("localStorage:", localStorage.getItem("usuario"));
console.log("Cookies:", document.cookie);

8. ORGANIZACIÓN DEL CÓDIGO EN MÚLTIPLES ARCHIVOS

A medida que los programas crecen en tamaño y complejidad, resulta necesario organizar el código de forma adecuada. En unidades anteriores, el código se ha desarrollado en un único archivo, lo que es válido en programas pequeños, pero se convierte en un problema en aplicaciones más grandes.

En esta unidad se introduce la modularización del código, es decir, la división del programa en diferentes archivos, cada uno con una responsabilidad concreta. Este enfoque permite desarrollar aplicaciones más claras, reutilizables y mantenibles, y es el utilizado en el desarrollo profesional.

8.1 PROBLEMA DEL CÓDIGO EN UN ÚNICO ARCHIVO

Cuando todo el código se encuentra en un solo fichero:

  • Se vuelve difícil de leer
  • Es complicado de mantener
  • Se incrementa la probabilidad de errores
  • Se dificulta la reutilización

Ejemplo de mala práctica:

// Archivo con muchas funciones mezcladas
function sumar(a, b) { return a + b; }
function guardar() { ... }
function mostrar() { ... }

Si el código crece, es necesario organizarlo correctamente

8.2 CONCEPTO DE MODULARIZACIÓN

La modularización consiste en dividir el código en módulos, es decir, archivos independientes que contienen funcionalidades específicas.

Cada módulo debe tener una única responsabilidad, por ejemplo:

  • funciones matemáticas
  • gestión de almacenamiento
  • lógica principal

Ejemplo de estructura

proyecto/
│
├ index.html
├ js/
│ ├ app.js
│ ├ funciones.js
│ ├ storage.js
│
└── css/

La modularización ofrece múltiples ventajas, entre las que se pueden destacar:

  • Mejora la organización del código
  • Facilita la reutilización
  • Permite trabajar en equipo
  • Reduce la duplicación
  • Hace el código más profesional

8.3 USO DE MÓDULOS EN JAVASCRIPT (ES MODULES)

JavaScript permite dividir el código en diferentes archivos mediante el uso de módulos. Para ello, se utilizan las palabras clave export e import, que permiten compartir código entre archivos.

8.3.1 Exportación nombrada (forma recomendada)

La exportación nombrada permite exportar varias funciones o variables desde un mismo archivo.

Forma básica

// funciones.js
export function sumar(a, b) {
    return a + b;
}

export function restar(a, b) {
    return a - b;
}

Cada elemento se exporta de forma individual.

Importación

// app.js
import { sumar, restar } from "./funciones.js";

console.log(sumar(2, 3));

Es obligatorio usar llaves {} porque se trata de exportaciones nombradas. Permitiendo exportar varios elementos, para importarlos por su nombre exacto.

8.3.2 EXPORTACIÓN AGRUPADA (FORMA ALTERNATIVA Y MÁS CLARA)

Otra forma más estructurada es definir las funciones primero y exportarlas al final:

// funciones.js
function sumar(a, b) {
    return a + b;
}

function restar(a, b) {
    return a - b;
}

export { sumar, restar };

8.3.3 EXPORTACIÓN POR DEFECTO (DEFAULT)

Cuando un archivo tiene un único elemento principal, se puede usar exportación por defecto.

Ejemplo

// saludo.js
export default function saludar(nombre) {
    return "Hola " + nombre;
}

Importación

import saludar from "./saludo.js";

Diferencias clave

8.4 CONFIGURACIÓN EN HTML

Para que los módulos funcionen correctamente, es necesario indicar en el HTML que el script es de tipo módulo:

<script type="module" src="js/app.js"></script>

Características de los módulos

  • Cada archivo tiene su propio ámbito
  • No contaminan el espacio global
  • Permiten importar y exportar código

Los módulos requieren un servidor para funcionar correctamente, esto significa que no funcionan con: file://. Por tanto, necesitaremos alojarlos en un servidor web o simular un servidor con Live Server (Visual Studio Code)

8.5 SEPARACIÓN DE RESPONSABILIDADES

Una de las ideas clave en la modularización es que cada archivo debe encargarse de una tarea concreta.

Ejemplo

//funciones.js
export function doble(n) {
    return n * 2;
}
//storage.js
export function guardar(nombre) {
    localStorage.setItem("usuario", nombre);
}
//app.js
import { doble } from "./funciones.js";
import { guardar } from "./storage.js";

let numero = 5;
console.log(doble(numero));

guardar("Ana");

¿Qué hemos logrado?

  • Evitar funciones que hacen demasiadas cosas
  • Mejorar la claridad del programa
  • Facilitar el mantenimiento

8.6 REUTILIZACIÓN DEL CÓDIGO

Una de las grandes ventajas de los módulos es la posibilidad de reutilizar código. Por ejemplo, una función definida en un archivo puede utilizarse en múltiples proyectos.

Ejemplo

// funciones reutilizables
export function esPar(n) {
    return n % 2 === 0;
}

8.7 BUENAS PRÁCTICAS EN MODULARIZACIÓN

Es importante introducir ciertas normas:

  • Usar nombres claros para los archivos
  • Agrupar funcionalidades relacionadas
  • Evitar archivos demasiado grandes
  • Importar solo lo necesario
  • Mantener estructura coherente

9. DEPURACIÓN Y DOCUMENTACIÓN DEL CÓDIGO

El desarrollo de software no consiste únicamente en escribir código que funcione, sino también en asegurarse de que ese código es correcto, comprensible y fácil de mantener. Para ello, es fundamental trabajar dos aspectos clave:

  • La depuración del código
  • La documentación del código

Ambos elementos forman parte del proceso de desarrollo profesional y permiten mejorar la calidad de los programas.

9.1 DEPURACIÓN DEL CÓDIGO

La depuración es el proceso de identificar, analizar y corregir errores en un programa. Durante el desarrollo es habitual cometer errores, por lo que es necesario utilizar herramientas y técnicas que permitan detectarlos y solucionarlos.

9.1.1 USO DE CONSOLE.LOG()

La herramienta más utilizada en este nivel es console.log(), que permite mostrar información en la consola del navegador, a medida que usemos JavaScript para desarrollar aplicaciones webs profesionales, dejaremos esta herramienta para tareas de depuración relacionadas como:

  • comprobar valores de variables
  • verificar resultados
  • entender el flujo del programa

9.1.2 PRUEBAS CON DISTINTOS DATOS

Para comprobar que un programa funciona correctamente, es necesario probarlo con diferentes tipos de datos.

Ejemplo

let numero = Number(prompt("Introduce un número"));
console.log(numero * 2);

Sería necesario probar con:

  • números positivos
  • números negativos
  • cero
  • texto

9.1.3 USO DE LAS HERRAMIENTAS DEL NAVEGADOR

El navegador proporciona herramientas de desarrollo accesibles mediante, F12 o botón derecho → Inspeccionar, estas herramientas nos permiten:

  • ver la consola
  • analizar errores
  • inspeccionar código

9.2 DOCUMENTACIÓN DEL CÓDIGO

La documentación del código consiste en añadir información explicativa dentro del programa para facilitar su comprensión.

9.2.1 DOCUMENTACIÓN EN PROYECTOS MODULARES

Cuando se trabaja con varios archivos, la documentación cobra mayor importancia.

Ejemplo

// funciones.js
/*
Funciones matemáticas básicas
*/
export function sumar(a, b) {
    return a + b;
}

Las principales ventajas de documentar los módulos son:

  • Facilita el trabajo en equipo
  • Permite entender el código sin analizarlo completamente
  • Mejora el mantenimiento

9.2.2 BUENAS PRÁCTICAS EN DOCUMENTACIÓN

  • Escribir comentarios claros y concisos
  • Evitar comentarios innecesarios
  • Mantener la documentación actualizada
  • Documentar especialmente funciones y módulos

9.3 RELACIÓN ENTRE DEPURACIÓN Y DOCUMENTACIÓN

Ambos procesos están estrechamente relacionados:

  • la depuración permite corregir errores
  • la documentación permite entender el código

En definitiva, un código bien documentado es más fácil de depurar.

10. CONCLUSIONES

En esta unidad el alumnado ha dado un paso fundamental en su proceso de aprendizaje, pasando de la programación estructurada desarrollada en unidades anteriores a la interacción con un entorno real de ejecución: el navegador web.

A lo largo de la unidad, se ha trabajado con los objetos nativos del lenguaje, que permiten simplificar el desarrollo mediante el uso de funcionalidades ya implementadas, favoreciendo la eficiencia y la reutilización del código. Asimismo, se han introducido los objetos predefinidos del navegador, especialmente el objeto window, que permite establecer una primera interacción con el usuario y comprender cómo el código puede influir en el entorno.

Uno de los aspectos más relevantes ha sido la introducción del concepto de contenido dinámico, permitiendo al alumnado generar y modificar información en la página web. Este punto resulta clave, ya que establece las bases para el trabajo posterior con el DOM, donde la manipulación del documento se realizará de forma más estructurada y profesional.

Además, se ha abordado la gestión de la ventana del navegador y la creación de nuevas ventanas, lo que ha permitido comprender mejor el funcionamiento del entorno cliente y la relación entre distintos contextos de ejecución.

Otro bloque fundamental ha sido el almacenamiento de información en el navegador, mediante el uso de localStorage y cookies, introduciendo el concepto de persistencia de datos. Este aprendizaje acerca al alumnado a situaciones reales en las que es necesario mantener información entre sesiones, mejorando la experiencia de usuario.

Especial relevancia tiene la introducción de la organización del código en múltiples archivos mediante módulos, ya que supone un cambio hacia prácticas propias del desarrollo profesional. El alumnado ha aprendido a estructurar aplicaciones, separar responsabilidades y reutilizar código, aspectos esenciales en proyectos reales y en el uso de frameworks modernos.

Por último, se han trabajado las técnicas de depuración y documentación del código, fundamentales para garantizar la calidad del software. El uso de herramientas como la consola del navegador y la incorporación de comentarios adecuados permiten desarrollar programas más fiables, comprensibles y mantenibles.
